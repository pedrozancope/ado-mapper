# ADO Mapper (local)

A browser-only Excel/CSV to Azure DevOps creation-CSV mapper, designed for macOS.
Source files remain in browser memory. The local server only serves app assets;
it cannot receive uploaded files and the app makes no external data requests.
There is no telemetry, cloud storage, ADO login, or automatic work item creation.

## Run

Requires Node.js 20 or newer.

```sh
npm install
npm start
```

Open **http://127.0.0.1:4173**. After dependencies are installed, the app works
offline. Keep the terminal running; press Control-C to stop it. The server binds
only to loopback, not your network.

For development, `npm run dev` watches the source folder and restarts the server
when JavaScript changes. Refresh the browser to load client changes.

## Workflow

1. Open an `.xlsx` or UTF-8 `.csv` file. Select the worksheet and header row.
   [`assets/examples/Example.xlsx`](./assets/examples/Example.xlsx) contains the original two-row example.
2. Review the suggested mappings. Each enabled row becomes one CSV column.
   Choose exact standard field names from the preloaded dropdown. Use **Custom
   field…** for a project-specific CSV display name, not a reference name such
   as `System.Title`. Reorder mappings using the up/down buttons.
3. Select a source column, or choose **Constant / default only**. Defaults apply
   only to empty source values; `0` and `FALSE` are preserved. Prefixes and
   suffixes wrap nonblank values. For example, prefix `YourProject\` turns
   `Sprint 1` into `YourProject\Sprint 1` for **Iteration Path**.
   To use a fixed iteration root with an optional Sprint, select **Iteration
   root + Sprint** as the text format for **Iteration Path**, put the root in
   **Default / constant**, select the Sprint source column, and leave prefix and
   suffix blank. Only the segment after the last `\` in the source is appended;
   blank Sprint values use the root alone. A trailing `\` in the root is optional.
4. Optionally filter a source column by an exact, case-insensitive value.
   Whitespace is significant. A blank filter value selects blank cells.
   Hidden rows and Excel's worksheet filters do not affect the imported data.
5. Optionally configure an existing Epic parent and choose text formatting
   (see below). Resolve validation errors and review the preview. It displays
   the first 100 rows in the selected batch, with a non-exported source-row
   identifier. Parent references are highlighted.
6. Download the CSV directly: UTF-8 with BOM, comma-delimited, fully quoted,
   preserving quotes and multiline/HTML content. Each batch has at most **1,000**
   total rows, including existing parent references. For larger inputs, download all batches as a ZIP, extract it,
   and import each CSV separately. No manual Excel "Save as" step is necessary.
7. In your target ADO project, choose **Boards > Queries > Import work items**,
   select the CSV, review ADO validation, then **Save items**.

## Reuse mappings

**Save profile** downloads a versioned JSON file containing mappings and the
filter, rich-text formats, parent settings, and the editable Epic lookup table. **Load profile** restores it,
including before loading source data. Version 1 profiles remain supported and
retain plain-text behavior with parent mode disabled. Version 2 profiles retain
their existing direct-ID parent behavior. New profiles use version 3.
Mappings are retained when you load another source in the same browser tab;
missing source headers block export rather than silently falling back.
Source rows are never included in profiles. Default/prefix/filter settings
may contain sensitive data, so store profile files securely.

Closing/reloading the page clears the source data and unsaved mapping changes.

## Rich Description and Acceptance Criteria

ADO imports HTML in HTML-typed fields. The **Text format** setting controls
conversion of source text to portable HTML:

- **Plain text**: unchanged output (also the behavior of old profiles).
- **Paragraphs (HTML)**: blank lines separate paragraphs; single line breaks
  become `<br>`.
- **User story (HTML)**: detects `As a ... I want to ... so that ...` and creates
  three paragraphs with bold labels. Other text uses paragraph formatting.
- **Markdown → HTML**: `#`, `##`, `###` headings; `**bold**` / `__bold__`;
  `*italic*`; inline backtick code; `-`, `*`, `+` bullets; and numbered lists
  (`1.` / `1)`). Blank lines separate paragraphs; single line breaks remain.
  This is a small supported subset, not a complete Markdown engine.

New suggested mappings use User story formatting for Description and Markdown
for Acceptance Criteria. The rendered preview shows those styles; uncheck
**Render formatted HTML fields** to see exact exported HTML. Source HTML is
escaped, never rendered or executed. Raw HTML pass-through is not supported.
Excel cell fonts/colors are not copied. Use formatting modes only for ADO HTML
fields (Description, Acceptance Criteria, Repro Steps, System Info, or suitable
custom fields). Title and Work Item Type must remain plain text.

ADO may normalize styling on import. Review a small test import in your project
before a large run; this app cannot verify the resulting ADO UI.

## Link User Stories to existing Epics

Enable **Link to existing Epics** under **Link stories by Epic name**. The
default mode is **Epic names in my sheet → look up ADO IDs below**:

1. Choose **Column in your spreadsheet containing Epic names** (usually `Epic`;
   this header is selected automatically when present).
2. Review the preloaded table of **21 Epics from your supplied screenshot**.
   It is a fixed starter catalog, not a live ADO query.
3. Edit/add rows with **Epic name in your spreadsheet**, **Existing ADO Epic ID**,
   and **Current Epic title in ADO**. For example, source `Products` can map to
   ID `1572173` with the ADO title `Product Discovery`. The source name may differ
   from the ADO title; only the ADO title is written to the parent reference row.
4. Source names match ignoring case and leading/trailing spaces. Spelling,
   internal spaces and punctuation remain significant; no fuzzy matching.
   The **Source rows** count includes all nonempty source rows, before export
   filtering. Blank/unmatched Epic names in selected rows block export.
5. Use **Save profile** to reuse the full table. Edits are kept in the current
   tab across source-file changes, but unsaved edits reset on reload.

Duplicate source names, invalid IDs, empty titles, conflicting titles for the
same ID, and missing source columns also block export. Multiple different
source aliases may target the same ID if their current ADO titles agree.
IDs and ADO titles are trimmed when exported. Source IDs are not needed for
lookup mode. Confirm screenshot titles against your current ADO project,
especially punctuation and spacing, before importing.

**Advanced: my sheet already contains ADO IDs / use one fixed ID** preserves
the earlier direct mode. Choose actual Epic ID/title columns or enter fixed
values (also used for blank cells). Never apply one fixed ID to an unfiltered
source containing different Epic names unless all those stories truly share
that parent. Source story IDs are not Epic IDs.

The CSV uses Microsoft's documented indented-title layout:

```csv
ID,Work Item Type,Title 1,Title 2,Description
165,Epic,Current Epic title,,
,User Story,,New story title,<p>Story description</p>
```

Existing Epics are reference rows, not new Epics. Child ID cells are blank;
ordinary ID/Parent mappings are still blocked. Only Epic ID, Work Item Type and
Title 1 are populated on reference rows; all other fields are blank.
**Providing a different Epic title may update that existing Epic**. Supply its
exact current title and review ADO's unsaved import before choosing Save items.
The app cannot verify that an ID exists, is an Epic, belongs to your project,
or matches the supplied title.

Stories are grouped by Epic in order of first appearance; order within each
Epic is preserved. Each CSV has at most 1,000 rows **including** references.
An Epic with more than 999 children spans batches, with the same reference
repeated at the start of each continuation batch. A parent is never left alone
at the end of a batch without a child. ZIP and single-CSV downloads share this
layout. The preview counts new items separately from exported batch rows.

This mode currently supports User Story children only. Direct Epic → User Story
links skip the usual Agile Epic → Feature → User Story backlog structure and
may not display as expected in feature-level backlog views. ADO/project rules
still apply. This feature does not create new Epics or Features.

## Preloaded standard fields

The dropdown provides standard creation-oriented fields across Agile, Scrum,
Basic and CMMI. It prevents spelling mistakes when choosing a standard name;
**Custom field…** remains explicitly editable. It is not a live project schema
or a claim that every field is supported by every work item type. Read-only and
blocked creation fields are deliberately excluded. Custom fields and allowed
values must still be confirmed against your project. No network access or
credentials are needed.

## Important limitations

- This is a **new work items** workflow, not an update workflow. **Work Item Type**
  and **Title** are required. Defaults suggest **User Story** for Agile; change
  to Product Backlog Item, Issue, Requirement, Task, or a valid custom type as
  needed. Titles must not be blank or exceed 255 characters.
- ID, State, Assigned To, Created By, Created Date, Changed By, and Changed Date
  are blocked as ordinary mappings. ID is generated only on existing Epic
  reference rows in parent mode. ADO sets the initial state. Perform
  assignment/state updates separately after creation.
- The app cannot validate your target project's custom fields, process,
  permissions, allowed values, or area/iteration paths. Confirm these using an
  export from your project and resolve ADO errors before saving.
- Without parent mode, work items remain flat. Parent mode uses the indented
  layout above; Epic/Feature names alone do not create links.
- Excel formulas are **not recalculated** by the app. It reads cached results.
  Recalculate and save in Excel before loading. Missing formula caches or Excel
  errors explicitly block export. Empty string formula caches are preserved using
  the workbook's XML cache metadata. Formatting-only rows are ignored.
- Dates are converted to ISO 8601. Numeric formatting is not preserved; store
  identifiers with leading zeros as text in the source workbook.
- Blank and duplicate source headers are rejected. Choose the correct header
  row or fix the source. CSV supports commas, semicolons, or tabs with automatic
  detection and a manual override. Legacy `.xls` is not supported.
- Reimporting a successful creation CSV creates duplicate work items.
- Plain text is preserved exactly; other modes intentionally convert it to
  escaped HTML. Untrusted text beginning with formula
  characters may be interpreted as formulas if you open the CSV in a spreadsheet
  app. Prefer the ADO importer or a plain text editor for inspection.

## Tests

```sh
npm test
```

Tests cover CSV parsing/roundtrips, example XLSX cached values, field validation,
defaults, zero/false values, source filtering, profiles, and 1,000-item batching.
Additional tests cover safe HTML generation, indented hierarchy rows, parent
validation, preloaded name-to-ID lookups, aliases, unmatched/duplicate names,
profile migration, and limits including repeated Epic references.
